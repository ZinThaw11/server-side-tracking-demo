Server-Side Tracking Briefing

A plain-English guide to what you're building and why it matters.

How It Works

Browser-Side Only (current)
User visits site → Browser fires GTM → GTM sends data to GA4 / Meta
Ad blockers, iOS privacy, and browser restrictions can block this entirely.
Server-Side (what you're adding)
User visits site → Browser fires GTM → GTM sends data to YOUR server → Server sends data to GA4 / Meta
Requests go through your server first — ad blockers can't touch it.

What Stape Does

Stape hosts your GTM server container for free. Instead of managing your own server, Stape handles it. Your GTM web container sends data to Stape, and Stape forwards it to GA4 and Meta. You get a server URL like https://xxxxx.stape.io — that's where all your data flows through.

The 5 Steps

  1. 1

    Create Stape Account + Server Container

    Sign up at stape.io (free tier). Stape gives you a server URL — this is where your data will flow through.

  2. 2

    Connect Web Container to Server Container

    In GTM, tell your web container to send GA4 and Meta data to your Stape server URL instead of directly to Google and Meta.

  3. 3

    Migrate GA4 to Server-Side

    Replace the direct GA4 tag with a tag that sends to Stape first, then Stape forwards to GA4.

  4. 4

    Set Up Meta Pixel + CAPI

    Meta Pixel fires from the browser. CAPI sends a duplicate from the server. Both hit Meta — with deduplication so events aren't counted twice.

  5. 5

    Test with Ad Blocker

    Install an ad blocker, block the browser pixel — confirm server-side still fires. This is your proof for the LinkedIn post.
